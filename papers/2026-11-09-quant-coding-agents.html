Beyond Accuracy: How Quantization Affects Coding Agents
— 4-bit weights leave the final score statistically unchanged, but change how the agent gets there and how it fails — 4비트 가중치는 최종 점수를 통계적으로 바꾸지 않지만, 에이전트가 답에 이르는 방식과 실패하는 방식을 바꾼다

Workshop · SLM-Agents @ NeurIPS'26
👥 Areej Mehboob, Muhammad Ali Shafique, Muhammad Usman Qadeer, Hamza Farooq 🏛 Traversaal AI · Kansas State University 🗓 2026-11-02 📄 arXiv:2611.02368
⚡ TL;DR
  • Motivation동기Coding agents make many model calls in an execute-and-revise loop, so 4-bit weights are tempting, yet quantization studies usually score single-pass outputs.코딩 에이전트는 실행하고 고치는 루프에서 모델을 여러 번 부르므로 4비트 가중치가 매력적이다. 하지만 양자화 연구는 대개 한 번 생성한 출력만 채점한다.
  • Analysis분석In an agent, quantization can change tool use, revision, and how runs end, not only whether the final program passes.에이전트에서는 양자화가 최종 프로그램의 통과 여부뿐 아니라 도구 사용, 수정 과정, 실행이 끝나는 방식까지 바꿀 수 있다.
  • Method방법Run BF16, AWQ and GPTQ 4-bit versions of Qwen2.5-Coder 7B/14B/32B and Devstral 24B on 115 OJBench problems with a Python executor, three seeds, and paired tests on solves, trajectories and failure types.Qwen2.5-Coder 7B/14B/32B와 Devstral 24B의 BF16, AWQ, GPTQ 4비트 버전을 파이썬 실행기와 함께 OJBench 115문제에 돌리고, 시드 3개로 풀이 수와 궤적, 실패 유형을 짝 검정한다.
  • Results결과No agent loses significant accuracy, yet Qwen-7B's one-shot solves drop from 17 to 0 under AWQ while loop-based solves rise from 10 to 25.어떤 에이전트도 유의한 정확도 손실은 없지만, AWQ에서 Qwen-7B의 한 번에 푼 문제는 17에서 0으로 줄고 루프로 푼 문제는 10에서 25로 는다.
💭 Intuition💭 직관

Two students get the same grade on a programming exam. One wrote correct code straight away; the other had to run it several times and fix bugs. The grade hides the difference, which matters when test runs are slow or limited. A 4-bit model can keep the grade while turning into the second student.

두 학생이 프로그래밍 시험에서 같은 점수를 받았다. 한 명은 처음부터 맞는 코드를 썼고, 다른 한 명은 여러 번 실행하며 버그를 고쳤다. 점수는 이 차이를 숨기지만, 실행이 느리거나 횟수가 제한되면 그 차이가 중요하다. 4비트 모델은 점수는 지키면서 두 번째 학생처럼 바뀔 수 있다.

How it works: one agent loop, three precisions작동 방식은 하나의 에이전트 루프와 세 가지 정밀도

Every precision runs the same loop on the same problems and seeds, so each outcome can be compared pair by pair.

모든 정밀도가 같은 문제와 시드로 같은 루프를 돌기 때문에, 결과를 하나씩 짝지어 비교할 수 있다.

  1. Quantize.양자화.AWQ and GPTQ make 4-bit-weight copies of each model with 256 calibration samples, cutting checkpoints about 3.4×.AWQ와 GPTQ로 보정 샘플 256개를 써서 모델마다 4비트 가중치 사본을 만든다. 체크포인트는 약 3.4배 작아진다.
  2. Run the loop.루프 실행.The agent can test code on the examples and revise, with up to five tool calls per problem and a 32K context.에이전트는 예제로 코드를 시험하고 고칠 수 있으며, 문제당 도구 호출은 최대 5번, 맥락은 32K다.
  3. Compare in pairs.짝지어 비교.McNemar tests on 345 problem–seed pairs for accuracy, plus solve paths and five failure categories.문제와 시드 쌍 345개에 McNemar 검정을 적용해 정확도를 비교하고, 풀이 경로와 다섯 가지 실패 유형도 본다.

Key point: same score, different path핵심은 같은 점수, 다른 경로

Quantized Qwen-7B almost never solves a problem on its first try; it reaches a similar total by leaning on the execution loop.

양자화한 Qwen-7B는 첫 시도로 문제를 거의 풀지 못하고, 실행 루프에 기대어 비슷한 총합에 도달한다.

Results: failures change shape, scores hold결과는 점수는 유지되고 실패의 모양이 바뀜

For Devstral, quantization moves failures away from runtime crashes toward wrong answers and timeouts, the clearest shift in the study.

Devstral에서는 양자화가 실패를 실행 중 오류에서 오답과 시간 초과 쪽으로 옮긴다. 연구에서 가장 뚜렷한 변화다.

Final accuracy moves by at most about 3 points, and no drop survives correction for multiple tests.

최종 정확도는 많아야 약 3점 움직이고, 다중 검정 보정을 거치면 유의한 하락은 하나도 남지 않는다.

💡

When you quantize an agent, log tool calls, revision rounds and failure types, not just pass rate. A model that now needs more loops costs more time and calls even at the same accuracy.에이전트를 양자화할 때는 통과율만 보지 말고 도구 호출, 수정 횟수, 실패 유형을 기록하자. 정확도가 같아도 루프가 더 필요해진 모델은 시간과 호출을 더 쓴다.

⚠️

A small study: 115 problems, three seeds, and accuracy under 14%, so there are few solves to compare. "No significant loss" partly reflects low power; Qwen-32B drops about 3 points with p = 0.051 at the problem level.작은 연구다. 문제 115개, 시드 3개에 정확도가 14% 아래라 비교할 풀이 수가 적다. "유의한 손실 없음"은 검정력이 낮은 탓도 있으며, Qwen-32B는 약 3점 떨어지고 문제 단위 p는 0.051이다.
