Looping Deeper Without Growing the KV Cache: Recurrent Depth for Causal Encoder-Decoders
— loop the layers that write the shared cache, train them to settle, and eight passes cost no more memory than one — 공유 캐시를 쓰는 층을 반복시키고 한 점으로 수렴하도록 학습하면, 여덟 번 돌아도 메모리는 한 번 도는 모델과 같다

Preprint 🏛 UCSD · Hao Zhang
👥 Jiaqi Leng, Minshen Zhang, Zhaofeng Sun, Yu-Yang Qian, Peng Zhao, Hao Zhang (corresponding: Jiaqi Leng)(교신: Jiaqi Leng) 🏛 UC San Diego · Tsinghua University · Nanjing University 🗓 2026-11-09 📄 arXiv:2611.13378
⚡ TL;DR
  • Motivation동기Looped LMs add depth without parameters, but caching KV for every layer and every round caps how many requests a server can hold.루프 언어 모델은 파라미터 없이 깊이를 더하지만, 층마다 반복마다 KV를 저장하면 서버가 동시에 받을 수 있는 요청 수가 막힌다.
  • Analysis분석In a causal encoder-decoder, only a few encoder layers write global KV. Loops gain only when they refine that source, not when they re-read a frozen copy.인과 인코더-디코더에서는 인코더의 몇 층만 전역 KV를 쓴다. 반복은 그 원천을 다듬을 때만 효과가 있고, 고정된 사본을 다시 읽기만 해서는 효과가 거의 없다.
  • Method방법Loop the encoder block that writes global KV, train with a random number of rounds so it settles to a fixed point, and cache only the last round's KV.전역 KV를 쓰는 인코더 블록을 반복시키고, 반복 횟수를 무작위로 바꿔 가며 학습해 고정점에 수렴하게 한 뒤, 마지막 반복의 KV만 저장한다.
  • Results결과With 1/6 the global KV it keeps 86–93% of a looped Transformer's gain. On a looped 552B model the cache shrinks 36.8× and throughput rises 3.6×.전역 KV를 6분의 1만 쓰고도 루프 트랜스포머 이득의 86–93%를 유지한다. 루프를 건 552B 모델에서는 캐시가 36.8배 줄고 처리량이 3.6배 오른다.
💭 Intuition💭 직관

Think of a team that revises one shared brief eight times. If everyone files every draft, the cabinet overflows. If the editor keeps polishing until the brief stops changing, only the final version needs filing. And the polishing must happen on the brief itself, not on readers rereading an old copy.

공유 보고서 하나를 여덟 번 고치는 팀을 생각해 보자. 초안을 전부 보관하면 캐비닛이 넘친다. 편집자가 보고서가 더 이상 바뀌지 않을 때까지 다듬는다면 최종본 하나만 보관하면 된다. 그리고 다듬는 대상은 보고서 자체여야 한다. 독자가 옛 사본을 다시 읽는 것으로는 나아지지 않는다.

How it works: where and how to loop작동 방식은 어디를, 어떻게 반복할지

Two kinds of sharing stack up. CED shares global KV across layers, and the fixed point shares it across rounds.

두 가지 공유가 겹친다. CED는 층 사이에서 전역 KV를 공유하고, 고정점은 반복 사이에서 공유하게 만든다.

  1. Loop the encoder.인코더 반복.Repeat layers 2–5, which include the global KV source. A decoder loop, which only reads a frozen cache, captures 16–40% of the gain.전역 KV 원천이 들어 있는 2–5층을 반복한다. 고정된 캐시를 읽기만 하는 디코더 반복은 이득의 16–40%밖에 얻지 못한다.
  2. Train with random depth.무작위 깊이로 학습.Sample the round count from a Poisson with mean 8. The core then contracts to a fixed point, while a fixed 8-round model falls into a period-4 cycle.반복 횟수를 평균 8인 푸아송 분포에서 뽑는다. 그러면 코어가 고정점으로 수렴하고, 8번으로 고정해 학습한 모델은 주기 4의 순환에 빠진다.
  3. Cache the last round.마지막 반복만 저장.Every round of a new token reads past tokens' final-round KV. BPB moves by at most 0.0002.새 토큰의 모든 반복이 이전 토큰들의 마지막 반복 KV를 읽는다. BPB 변화는 최대 0.0002다.

Key point: memory, not compute, was the wall핵심은 막힌 곳이 연산이 아니라 메모리였다는 것

On one 4×GB200 node, caching KV per layer and per round cannot fit a single 128K request. Looped CED fits 38.

4×GB200 노드 하나에서 층마다 반복마다 KV를 저장하면 128K 요청 하나도 들어가지 않는다. Looped CED는 38개가 들어간다.

💡

The LoopVQ card (Nov 11) compressed a cache that grows with every loop. This paper avoids that growth by training the loop to converge. If you build looped models, try stochastic depth before reaching for cache compression.11월 11일 LoopVQ 카드는 반복마다 커지는 캐시를 압축했다. 이 논문은 반복이 수렴하도록 학습해서 캐시가 커지는 것 자체를 피한다. 루프 모델을 만든다면 캐시 압축 전에 무작위 깊이 학습부터 시도해 보자.

⚠️

Quality is shown only on models up to 340M with a 2,048-token context. The 552B runs use weights never trained to loop, so they measure cost, not quality. The encoder loop also makes prefill pricier on prompt-heavy workloads.품질은 340M 이하 모델과 2,048 토큰 문맥에서만 보였다. 552B 실험은 루프 학습을 하지 않은 가중치를 썼으므로 품질이 아니라 비용만 잰 것이다. 인코더 반복 탓에 프롬프트가 긴 작업에서는 프리필 비용도 커진다.
